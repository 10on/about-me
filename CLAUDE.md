# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal website for Дэнчик. Static site deployed on Cloudflare Pages. No build step — plain HTML/CSS/JS. Bilingual: Russian at the root, English mirrored under `en/` (see "Bilingual site" below).

## Local development

Open `index.html` via a local HTTP server (required for `fetch()` to load JSON):

```bash
python3 -m http.server 8000
# or
npx serve .
```

## Architecture

Blog-style site, one real HTML page per view (no client-side router):

- `index.html` — home: short intro + recent notes feed + article previews
- `notes.html` — full notes list with client-side tag filter
- `articles.html` + `articles/<slug>.html` — article list and reader pages, generated by `build.py`
- `about.html` — bio, timeline
- `lego.html` / `retro.html` / `diy.html` / `games.html` — topic pages: highlights block + notes-by-tag, then existing detailed content (lego collection w/ filters, retro device write-ups, DIY list, games device list)
- `projects.html` — LEGO project progress, linked from `lego.html`
- `style.css` — all styles, CSS custom properties in `:root`, dark theme via `[data-theme="dark"]`
- `main.js` — shared by `index.html`/`lego.html` only (theme toggle, `STATUS_LABELS`, photo modal); other pages duplicate a small inline theme-toggle/footer-year script instead
- `data/*.json` — content for lego, lego-projects, games. `data/notes.json` is generated by `build.py` from `content/notes/*.md` — don't hand-edit it, edit the source and rebuild.
- `content/*.md` + `build.py` — markdown → static HTML. `content/retro.md`/`content/diy.md`/`content/about.md` inject into `<!-- BUILD:slug -->` markers on `retro.html`/`diy.html`/`about.html` (`TARGETS` dict in `build.py`, optional per-slug wrapper CSS class — `about` uses `bio-content` instead of the default `md-content`). `content/articles/*.md` (filename `YYYY-MM-DD-slug.md`, with a front-matter block: `title`, `tags`, `date`, `read`, `excerpt`) generate `articles/<slug>.html` and the list/preview blocks on `articles.html`/`index.html`, each with its own meta description/canonical/OG tags. `content/notes/*.md` (filename `YYYY-MM-DD-slug.md`, front-matter `date` + `tags`) generate `data/notes.json` — markdown body paragraphs are flattened into one `text` string joined with `<br><br>` (notes render as a single `innerHTML` blob, not a block layout). Run `python3 build.py` after editing content (requires `pip3 install markdown pillow` — Pillow is used to read image dimensions for `width`/`height` attributes on note `<img>` tags, to avoid layout shift) — GitHub Pages runs this automatically (see below), Cloudflare Pages does not. `build.py` also regenerates `sitemap.xml` from `STATIC_PAGES` + the current articles every run.
- `robots.txt` / `sitemap.xml` — basic SEO. `vote.html` is `noindex` (interactive tool, not content). `SITE_URL` in `build.py` (`https://10on.github.io/about-me`) is the canonical domain baked into sitemap/canonical/OG URLs — update it in `build.py` and in each static page's `<link rel="canonical">`/`og:url` if the site ever moves to a custom domain.

## Adding content

- **Notes**: add `content/notes/YYYY-MM-DD-slug.md` — front-matter `date`, `tags` (comma-separated), then a markdown body — then run `python3 build.py`.
- **Articles**: add `content/articles/YYYY-MM-DD-slug.md` with front-matter, then run `python3 build.py`.
- **Lego/games**: edit `data/*.json`. Each item supports:

```json
{
  "name": "...",
  "desc": "...",         // optional
  "status": "want|have|done|wip",  // optional
  "url": "https://..."  // optional, makes name a link
}
```

## Bilingual site (`en/`)

The site has a full English mirror under `en/` (e.g. `en/index.html`, `en/lego.html`), one directory deeper than root so `style.css`/`img/` are referenced as `../style.css`/`../img/...`; `data/*.json` and `main.js` stay same-level references because `en/` has its own local copies (`en/data/*.json`, `en/main.js`). `vote.html` is intentionally not translated (interactive personal tool, already `noindex`).

- **Markdown-sourced pages** (`about`/`retro`/`diy` bio content, notes): pair the Russian source with an English one using an `.en.md` suffix inserted before `.md`, e.g. `content/about.md` → `content/about.en.md`, `content/notes/2026-07-22-slug.md` → `content/notes/2026-07-22-slug.en.md`. `build.py` loops over both `ru` and `en` and skips generation for a slug/note if its `.en.md` counterpart doesn't exist — an English translation is optional per item. Run `python3 build.py` after adding/editing either language's markdown; it regenerates both `data/notes.json` and `en/data/notes.json`, and both `sitemap.xml` language trees.
- **JSON-sourced pages** (lego/lego-projects/retro wishlist): hand-maintain a parallel English copy under `en/data/*.json` (`en/data/lego.json`, `en/data/lego-projects.json`, `en/data/retro_wishlist.json`) — translate `desc`/`name` text fields, keep machine-parsed fields (set numbers, years, `status`, `progress`) unchanged, and remember `img` paths in `en/data/retro_wishlist.json` need a `../` prefix relative to root's `data/retro_wishlist.json` since `en/retro.html` lives one directory deeper.
- **Articles**: same `.en.md` pairing convention would apply under `content/articles/`, generating `en/articles/<slug>.html` — untested against real content since no articles exist yet in either language.
- **Static pages with no markdown/JSON source** (`notes.html`, `articles.html`, `games.html`, `projects.html` shell/nav text): hand-translated once as `en/notes.html` etc.; keep them in sync manually if the Russian page's static markup changes (nav labels, footer, headings).
- Every page (both languages) carries three `hreflang` alternate links (`ru`, `en`, `x-default`) pointing at each other, plus a `.lang-switch` header link (`EN`/`RU`) toggling between the two trees. JSON-LD `alternateName` intentionally keeps the Cyrillic name as an alias on English pages.
- `build.py` constants involved: `NAV_LABELS`, `BRAND`, `TAGLINE`, `STRINGS` (per-language UI strings), `TARGETS` (per-language build targets), `LANG_DIRS` (`{'ru': ROOT, 'en': ROOT / 'en'}`).

## Deploying

Two hosts, both auto-deploy on push to `master`:

- **GitHub Pages** — `.github/workflows/pages.yml` runs on every push: installs `markdown`, runs `python3 build.py`, uploads the repo root as the Pages artifact. Enable once in repo Settings → Pages → Source: "GitHub Actions". No local build step needed for this host.
- **Cloudflare Pages** — connected via the dashboard, no build command (output directory `/`), so it serves whatever HTML is committed as-is. Run `python3 build.py` locally and commit the generated HTML before pushing if you want Cloudflare's copy to reflect the latest content. `_headers` sets long `Cache-Control` lifetimes for `img/*`, `style.css`, `main.js` (Cloudflare Pages' [`_headers` convention](https://developers.cloudflare.com/pages/configuration/headers/)); GitHub Pages ignores this file.

## SEO

Every static page's `<head>` carries `meta description`, `canonical`, `og:*`, `twitter:*` — copy the block from an existing page (e.g. `lego.html`) when adding a new one, keep the URL in sync with `SITE_URL`. `index.html`/`about.html` additionally carry a `schema.org/Person` JSON-LD block (name "Денис Пушкарёв", alternateName incl. "DenchikBricks") — keep it in sync if bio/brand facts change. `og:image` is per-topic (`img/*-cover.*`) where a cover exists, `img/persik.jpg` elsewhere as the default site image. `llms.txt` (hand-maintained, [llmstxt.org](https://llmstxt.org/) format) lists the site's main pages for AI agents/crawlers — update it when adding or renaming a top-level page.

## Design tokens

All colors and fonts are in `style.css` `:root` (+ `[data-theme="dark"]` overrides). Accent color is `--accent: #C25A3A`. Fonts: `Newsreader` (serif body) + `Space Mono` (mono/labels), loaded from Google Fonts in every page's `<head>`.
